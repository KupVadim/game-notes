# MagicLink — краткая структура и руководство

## Обзор

- Предназначение: расширение `pymdownx.magiclink` автоматически конвертирует в ссылки URL, FTP, email, сокращает и генерирует ссылки на репозитории (GitHub, GitLab, Bitbucket) и упоминания в соцсетях (X). Объяснение: экономит время при написании документации, приводит длинные ссылки к компактному и читаемому виду.

## Быстрый пример включения

- Использование: `import markdown; md = markdown.Markdown(extensions=['pymdownx.magiclink'])`. Объяснение: подключение как обычного расширения Python‑Markdown.

## Auto-Linking (авто-ссылки)

- Поддержка: HTTP/HTTPS, FTP, email — можно вставлять как обычный текст. Объяснение: упрощает вставку суровых адресов без синтаксиса `<...>`.

- Ограничения: механизм агрессивно не линкует всё подряд — для сложных случаев используйте старый стиль `<https://...>` (angle bracket). Объяснение: предотвращает ложные ссылки.

```js
// Пример явного авто‑линка
`<`https://www.link.com`>`
```

## Сокращённые (shorthand) ссылки на репозитории

- Поддерживаемые типы: issues (`#num`), pulls (`!num`), discussions (`?num`), commits (hash), compares (`hash1...hash2`), репозитории (`user/repo`) и упоминания (`@user`). Объяснение: синтаксис близок к GitLab и позволяет компактно ссылаться на элементы кода.

- Контекст: требуется опция `provider` и, при необходимости, `user`/`repo` для сокращения относительных ссылок. Объяснение: чтобы правильно разрешать `#1` относительно текущего проекта.

- Нормализация: опция `normalize_issue_symbols` заставляет все типы ссылок отображаться с `#` (полезно для единообразия и CSS‑иконок).

## Конфигурация (основные опции)

- `repo_url_shorthand` / `social_url_shorthand`: включают распознавание шортхенгов для репозиториев и соцсетей. Объяснение: активируют parsing короткого синтаксиса.

- `repo_url_shortener` / `social_url_shortener`: сокращают длинные внешние URL в компактный вид при рендере. Объяснение: удобство чтения итоговой документации.

- `provider`, `user`, `repo`: задают контекст по умолчанию. Объяснение: позволяет писать `#1` вместо `owner/repo#1`.

- `shortener_user_exclude`: список исключений (нельзя воспринимать как user/repo). Объяснение: кроме правил, предотвращает ложные сокращения вроде `https://github.com/support`.

- `labels`: позволяет переопределить текст в тултипах (`commit`, `compare`, `issue`, `pull`, `mention`, `repository`). Объяснение: локализация и адаптация терминологии (напр., GitLab uses "Merge Request").

## Mentions и repository mentions

- Синтаксис пользователей: `@{user}` или `@{provider}:{user}`. Объяснение: позволяет указывать манименсы в соцсетях или на сторонних провайдерах.

- Репозитории как упоминания: `@{user}/{repo}` или `@{provider}:{user}/{repo}` — в выводе `@` опускается. Объяснение: удобно для ссылок на проект без визуального "@".

## Commits и Compare

- Commits: 40‑символьный hash или `{repo}@{hash}` / `{user}/{repo}@{hash}` / `{provider}:{...}`. Объяснение: полная совместимость с URL‑шаблонами провайдеров.

- Compare: `{hash1}...{hash2}` с теми же правилами префиксов. Объяснение: единый синтаксис для диффов между коммитами.

## Repository Link Shortener

- Поведение: длинные URL из Github/GitLab/Bitbucket распознаются и сокращаются до читабельного шортхенга. Объяснение: повышает читаемость документа.

- Исключения: список `shortener_user_exclude` по умолчанию предотвращает ложные сокращения (пример: `support`, `dashboard`). Объяснение: многие служебные пути не являются аккаунтами/репозиториями.

## Custom repository hosts (частные инстансы)

- Опция `custom`: добавляет провайдер с полем `type` (github/gitlab/bitbucket), `host` и `label`. Объяснение: поддержка self‑hosted инстансов.

- Подробности: `host` формирует паттерн с/без `www`, опция `www` переключает добавление `www`. Объяснение: хосты по-разному используют `www`.

```js
'custom': {
  'test': { 'type':'github', 'host':'http://test.com', 'label':'Test' }
}
```

## CSS и классы

- Классы: для репозиторов добавляется `magiclink` и дополнительные `magiclink-<type>` и `magiclink-<provider>`. Объяснение: позволяет селекторно стилизовать ссылки и добавлять иконки.

- Примеры классов: `magiclink-mention`, `magiclink-issue`, `magiclink-github`, `magiclink-x` и т.д. Объяснение: разделение семантики по типу и провайдеру.

!!! tip "Иконки через CSS"
    Пример практики: документация не включает CSS; пользователю предлагают взять исходники SCSS: https://github.com/facelessuser/pymdown-extensions/blob/master/docs/src/scss/extensions/_magiclink.scss и подставить свои иконки через `content` и `::before`.

## Admonitions и важные предупреждения

!!! warning "SaneHeaders"
    Рекомендация: использовать расширение SaneHeaders (https://facelessuser.github.io/pymdown-extensions/extensions/saneheaders/) чтобы избежать конфликтов синтаксиса с `#1` в начале строки — иначе Python‑Markdown воспримет это как заголовок.

!!! warning "Валидация ссылок"
    Ссылка не проверяется: MagicLink не валидирует существование issues, пользователей или репозиториев — неявные или ошибочные идентификаторы всё равно будут превращены в ссылки.

!!! note "User excludes"
    По умолчанию заданы исключения (см. `shortener_user_exclude`). Объяснение: предотвращают ложноположительные сокращения для системных путей провайдеров.

## Что чаще всего рекомендуют люди и почему

- Использовать `SaneHeaders`: объяснение — предотвращает конфликты `#`‑синтаксиса при начале строки и делает документы предсказуемыми.

- Включать `repo_url_shortener` при подготовке документации проекта: объяснение — повышает читаемость и делает ссылки более компактными и контекстно понятными.

- Писать `provider`, `user`, `repo` по умолчанию для репозитория проекта: объяснение — позволяет писать краткие `#num` и `@user` без полноты квалификации.

- Добавлять кастомный CSS для иконок: объяснение — визуально отличает типы ссылок и улучшает UX в документации.

## Риски, ограничения и спорные моменты

- Риск ложных ссылок: отсутствие валидации при генерации ссылок может вести к битым ссылкам или нежелательной утечке внутренних ссылок в публичной документации.

- Конфликты синтаксиса: `#1` в начале строки конфликтует с Markdown‑заголовками (решение: SaneHeaders).

- Провайдеры отличаются: GitHub уникально присваивает ID issues и PRs; GitLab/Bitbucket — номера могут пересекаться между типами, поэтому строгая интерпретация `!` vs `#` важна.

- User excludes требуют поддержания: для новых хостов/ранних путей могут потребоваться дополнительные исключения.

## Моя аналитическая оценка релевантности

- Выгодность: высокая для проектов с множеством ссылок на репозитории — экономит время и улучшает читаемость.

- Стоит ли включать по умолчанию: да, если документация привязана к одному провайдеру и команде — настроить `provider/user/repo` и `repo_url_shortener`.

- Когда избегать: публичные сборки документации, где риск вывода неверных ссылок критичен, или когда нужны строгие проверки ссылок.

## Вывод

- MagicLink удобно сокращает и автогенерирует ссылки для репозиториев и упоминаний; рекомендуется включать вместе с `SaneHeaders`, настраивать `provider/user/repo` и использовать `shortener_user_exclude` и кастомную CSS для контроля внешнего вида и предотвращения ложных сокращений.
